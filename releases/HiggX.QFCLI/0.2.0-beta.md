# Quotation Factory CLI v0.2.0-beta

This repository stores release metadata and downloadable assets only. Source code is built from Azure Repos.

Assets:
- qfc-cli.zip: cross-platform bundle with binaries, skills, and setup docs.
- qfc-win-x64.zip: Winget-compatible portable Windows package.
- qfc-skills.zip: agent skills for installation with qfc skills update.
- SHA256SUMS.txt: SHA256 checksums for release assets.

Release notes:

## 0.2.0-beta - 2026-08-25

### Added
- **Machine-to-machine (client-credentials) authentication for unattended callers.** `qfc` can now authenticate with an OAuth2 client-credentials service credential — no browser, no human, no token file — for scheduled jobs, CI, and cloud functions (e.g. an Azure Function reacting to platform events). Set `QFC_CLIENT_ID`/`QFC_CLIENT_SECRET` (optionally `QFC_AUTH_AUDIENCE`) and the CLI exchanges them for a short-lived token in memory on each call; or run `qfc auth login --client-id <id> --client-secret <secret>` to verify and persist a credential for interactive use. Auth precedence is client credentials → `QFC_ACCESS_TOKEN` → stored token file, and `qfc auth status` reports the active mode. Service credentials are least-privilege, party-scoped, and appear under a distinct `<client_id>@clients` identity in audit logs.

### Security
- **Fail closed on service credentials.** When a client credential is configured (env vars or stored file), the CLI authenticates *exclusively* with it and never falls back to a human token: a failed token exchange, an incomplete configuration (only one of client id/secret), a malformed or unreadable `client_credentials.json`, and an inaccessible credential path all resolve to "unauthenticated" rather than silently using `QFC_ACCESS_TOKEN` or the stored user token. `qfc auth login --client-id` verifies exactly the supplied arguments before persisting, so a failed rotation preserves the previous valid credential; the in-memory token cache is bound to a non-reversible fingerprint of its credential, effective audience, and domain (a rotation triggers an immediate re-exchange, never serving a stale token); and persisted credential files are owner-only (`0600`) on Unix. Generic error output never contains credential values.

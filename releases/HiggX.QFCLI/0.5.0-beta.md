# Quotation Factory CLI v0.5.0-beta

This repository stores release metadata and downloadable assets only. Source code is built from Azure Repos.

Assets:
- qfc-cli.zip: cross-platform bundle with binaries, skills, and setup docs.
- qfc-win-x64.zip: Winget-compatible portable Windows package.
- qfc-skills.zip: agent skills for installation with qfc skills update.
- SHA256SUMS.txt: SHA256 checksums for release assets.

Release notes:

## 0.5.0-beta - 2026-11-20

### Added
- **Customer Success integration — the `qfc cs` command group (and `--service interkwam`).** The CLI can now talk to the Customer Success team through the Interkwam support platform's customer-facing Messenger API (`/messenger/…`), the same channel as the in-app widget. A new service `interkwam` (aliases `cs` / `support` / `messenger` / `desk`) routes to it; the ergonomic `qfc cs` verbs wrap the endpoints. See the new `qf-support` skill and `docs/INTERKWAM_INTEGRATION.md`.
  - **Release notes / product updates** — `qfc cs updates` (active "Updates" feed + unread count), `qfc cs updates show <id>`, and `qfc cs updates read|seen|dismiss <id>` to clear an item from the unread badge.
  - **Knowledge-base answers** — `qfc cs ask "<question>"` searches the public help articles; `qfc cs article <slug>` reads one in full.
  - **Two-way conversations** — `qfc cs chat list|show|new|send`. `new`/`send` **auto-attach the live product context** (party / project / BOM / stage) read from a running `qfc serve`, so CS (and the AI) answer in context — override with `--party/--project/--bom/--stage/--route`, or disable with `--no-context` (`--context-port` selects the serve instance).
  - **KB-grounded AI answers** — `--ai` on `chat new`/`send` asks the AI to answer first; it posts into the thread or escalates to a human, returning the refreshed thread on stdout and the outcome (`answered`/`confidence`/`escalate`) on stderr. Public KB only; never quotes binding prices.
  - **Attachments** — `--file <path>` on `chat new`/`send` (repeatable; up to 5 files, 10 MB each), sent as multipart to the Messenger's `…/with-attachments` endpoints, with client-side validation (`INVALID_ATTACHMENT`).
  - **Notifications** — `qfc cs notify` (one-shot snapshot: unread count + emergency acks) and `qfc cs notify --watch` (streams live changes over the Messenger SSE endpoint `/messenger/events` as JSON lines, re-polling the unread count every `--poll-seconds`, auto-reconnecting). Emergency acknowledgements: `qfc cs ack list` / `qfc cs ack set <id>`.
- **Built-in Interkwam endpoints (DEV + PROD).** The per-environment host ships with the CLI: QF **prod** → `https://support.quotationfactory.com`, QF **dev** → `https://support-dev.quotationfactory.com` (from the Interkwam deployment's Front Door host). Interkwam has only DEV and PROD — on `--env uat` the `cs` commands report `INTERKWAM_API_NOT_CONFIGURED`. Override with `qfc config set interkwam-base-url <url>` / `QFC_INTERKWAM_BASE_URL`.
- **Messenger authentication (dedicated audience).** The Messenger validates Auth0 tokens for its own API audience `https://interkwam.rhodium24.io/messenger` (authority `https://auth.rhodium24.io`), **not** the backend audience — so a normal `qfc auth login` token is rejected with HTTP 401. Mint a Messenger token with `qfc auth login --client-id <id> --client-secret <secret> --audience https://interkwam.rhodium24.io/messenger`, or set `QFC_ACCESS_TOKEN` to one issued for that audience. The audience default is correct out of the box; `interkwam-audience` / `QFC_INTERKWAM_AUDIENCE` override it. All Interkwam config appears in `qfc config show`.
- **`qf-support` skill** — documents the whole `cs` command group (setup, auth, every command, equivalent raw `--service interkwam` calls, and an error-code reference).

### Changed
- **`qfc api` reports the correct not-configured error code per service** — an unconfigured `--service interkwam` call now returns `INTERKWAM_API_NOT_CONFIGURED` (previously the MTK code was reused for every not-configured service).

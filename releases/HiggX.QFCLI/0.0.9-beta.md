# Quotation Factory CLI v0.0.9-beta

This repository stores release metadata and downloadable assets only. Source code is built from Azure Repos.

Assets:
- qfc-cli.zip: cross-platform bundle with binaries, skills, and setup docs.
- qfc-win-x64.zip: Winget-compatible portable Windows package.
- qfc-skills.zip: agent skills for installation with qfc skills update.
- SHA256SUMS.txt: SHA256 checksums for release assets.

Release notes:

## 0.0.9-beta - 2026-08-23

### Added
- **`qfc mcp` — MCP 2.0 server** built on the official ModelContextProtocol C# SDK v2 (protocol revision 2026-07-28). Exposes access-scoped meta-tools (`list_surfaces`, `discover_endpoints`, `describe_endpoint`, `get_schema`, `call_api`) over the cached OpenAPI spec, partitioned into server surfaces (rfq / quotation / order / procurement / platform-config / portal-config / system) with `--access` (contributor/admin/system) and `--surface` scoping. Read-only by default; `--allow-writes` enables mutations.
- **MCP HTTP transport as an OAuth 2.1 resource server** (`qfc mcp --http`) integrated with Auth0: validates each caller's Auth0 JWT (`Authority`/`Audience` from settings), serves RFC 9728 Protected Resource Metadata at `/.well-known/oauth-protected-resource`, challenges unauthenticated calls with `401`, and forwards the caller's token to the backend. The stdio transport keeps using the stored qfc token — existing Auth0 support is unchanged.
- **`qfc service` — run as an OS service.** `install`/`uninstall`/`start`/`stop`/`status` register a long-running server (`mcp --http` by default, or `serve`) as a Windows service (`sc.exe`) or systemd unit (`Type=notify`, `Restart=on-failure`, optional `--user`/`--env-file`). `--print` previews both platforms' definitions without elevation. The `serve` and `mcp --http` hosts are now service-aware (`AddWindowsService`/`AddSystemd`).
- **qf-* skills exposed as MCP prompts.** The MCP server surfaces the skill files (`.claude/commands/*.md`) as prompts — clients discover them via `prompts/list` and pull a workflow via `prompts/get`, executing its steps through `call_api`. Prompts are filtered to the server's `--access`/`--surface` scope (a skill maps to surfaces via the endpoints it references; endpoint-less skills are always visible). Configurable with `--skills-dir` / `--no-prompts`.

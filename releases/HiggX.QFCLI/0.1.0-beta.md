# Quotation Factory CLI v0.1.0-beta

This repository stores release metadata and downloadable assets only. Source code is built from Azure Repos.

Assets:
- qfc-cli.zip: cross-platform bundle with binaries, skills, and setup docs.
- qfc-win-x64.zip: Winget-compatible portable Windows package.
- qfc-skills.zip: agent skills for installation with qfc skills update.
- SHA256SUMS.txt: SHA256 checksums for release assets.

Release notes:

## 0.1.0-beta - 2026-08-23

### Added
- **Per-caller scope on the HTTP transport (multi-tenant).** One authenticated `qfc mcp --http` instance now serves different tiers per caller: each request's scope is derived from the caller's Auth0 token roles (Reader/Contributor → contributor, Admin → +admin, SysAdmin → +system), capped by the instance `--access`/`--surface` ceiling. Tools and skill prompts both respect it. Tokens with no role/permission claim fall back to the instance scope, so it works with today's tokens and differentiates automatically once roles are emitted. Configure the roles claim via `Auth0RolesClaim`, or disable with `--no-per-caller-scope` (stdio always uses the fixed scope).
- **`whoami` tool + party isolation (centralized hosted service).** A `whoami` tool returns the caller's identity and the parties (companies) they can act on (from `/api/user`). On the authenticated HTTP transport, `call_api` refuses requests targeting a party the caller is not a member of (`PARTY_FORBIDDEN`) before they reach the backend — so one centralized instance (e.g. hosted by Quotation Factory for Customer Success, and listable in the ChatGPT/Claude MCP directories) isolates each caller to their own parties while cross-party users reach all of theirs. The MCP server now also advertises store-facing identity/instructions. Disable the check with `--no-party-check` (backend still enforces access).
- **File uploads and binary responses in `call_api`.** `call_api` now accepts a `files` array (each with a local `path` for stdio or base64 `contentBase64` for the hosted HTTP transport) plus multipart `form` fields, so agents can upload CAD geometry and drawings. Binary responses (PDF, zip, images) are returned base64-encoded up to 256 KB and reported with metadata beyond that, instead of being corrupted by text decoding.
- **Audit logging.** On the HTTP transport, `call_api` emits a structured stderr audit line per outcome (caller, method, path, surface, status — and the denial reason for out-of-scope, read-only, or cross-party refusals).
- **Hosting essentials.** `--bind` selects the HTTP listen address (default `127.0.0.1`; use `0.0.0.0` for containers), and an unauthenticated `/health` endpoint supports load-balancer and orchestrator probes.
- **`find_party` tool + paginated `whoami`.** `whoami` now returns the first `limit` parties (default 25) with a total count, and `find_party` searches the caller's parties by name — so an agent for a cross-party Customer Success user (who may belong to 100+ parties) can locate a company without dumping the whole list. The caller-profile cache is bounded (LRU), and a warning is logged when `/api/user` can't be reached and party isolation falls back to backend enforcement.
- **Confirmation gate for destructive actions.** `call_api` refuses destructive or customer-facing operations (DELETE, cancel, send, ERP export) until re-called with `confirm: true`, returning a `requiresConfirmation` result instead of executing — so an agent cannot delete, cancel, or send to a customer irreversibly in a single unattended step.

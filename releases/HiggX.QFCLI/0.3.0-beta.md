# Quotation Factory CLI v0.3.0-beta

This repository stores release metadata and downloadable assets only. Source code is built from Azure Repos.

Assets:
- qfc-cli.zip: cross-platform bundle with binaries, skills, and setup docs.
- qfc-win-x64.zip: Winget-compatible portable Windows package.
- qfc-skills.zip: agent skills for installation with qfc skills update.
- SHA256SUMS.txt: SHA256 checksums for release assets.

Release notes:

## 0.3.0-beta - 2026-08-27

### Added
- **Multi-environment support (prod / uat / dev).** The CLI can now target any of the three Quotation Factory deployment environments, each with its own API base URL, Auth0 audience, and web-app URL (Auth0 uses one shared tenant across all three). `prod` remains the default. Switch persistently with `qfc env use <name>`, or one-shot for a single command with the global `--env <name>` option or the `QFC_ENVIRONMENT` variable. `qfc env list` / `qfc env show` / `qfc env current` report the active environment and per-environment authentication state, and the active environment now appears in `qfc auth status` and `qfc config show`. A custom `api-base-url` (via `qfc config set`) is tracked as the `custom` environment and its URLs are never overwritten by a preset.
- **Per-environment token storage.** Each environment keeps its own stored access/refresh/client credentials, so switching between environments does not require re-login. `prod` keeps the existing unsuffixed token files (fully backward compatible); `uat`/`dev`/`custom` use `.<env>`-suffixed files (e.g. `token.uat`).

### Fixed
- `serve` and `ui` now derive the correct web-app URL per environment (`app-uat.rhodium24.io` / `app-dev.rhodium24.io`) instead of an incorrect/placeholder host, routed through the central environment registry.

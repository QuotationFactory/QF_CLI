# Quotation Factory CLI v0.4.0-beta

This repository stores release metadata and downloadable assets only. Source code is built from Azure Repos.

Assets:
- qfc-cli.zip: cross-platform bundle with binaries, skills, and setup docs.
- qfc-win-x64.zip: Winget-compatible portable Windows package.
- qfc-skills.zip: agent skills for installation with qfc skills update.
- SHA256SUMS.txt: SHA256 checksums for release assets.

Release notes:

## 0.4.0-beta - 2026-10-13

### Added
- **SCSN Document Exchange support.** New `qf-scsn` skill and CLI coverage for the SCSN (Smart Connected Supplier Network) endpoints live in the dev environment: provision/deprovision a party, manage the broker agent (retention, rate limit, sandbox), check the party's SCSN document configuration, and send UBL business documents (`Order`, `OrderResponse`, `Invoice`, `DespatchAdvice`, `QuotationResponse`).
- **`--service` switch for multi-service hosts.** A new global option (or `QFC_SERVICE`) targets a specific API on an environment host: `backend` (default, paths under `/api/…`) or `docsexchanger` (the SCSN Document Exchange API — broker messages + webhooks, paths under `/docsexchanger/v1/…`). Each service resolves its own call base URL and swagger URL and caches its spec separately, so `discover`/`describe`/`api` work against either. Aliases: `scsn`, `broker`. The Document Exchange URL is defined per environment — **only `dev` is formally defined today**; on `uat`/`prod` the CLI derives the expected same-host `/docsexchanger` URL by convention and warns it is unconfirmed (those services are not deployed yet). Set `QFC_DOCSEXCHANGER_BASE_URL` (or update the environment preset) once the real uat/prod URLs are published.
- **`qfc scsn listen` — inbound SCSN webhook receiver.** Hosts the broker webhook endpoint locally: verifies every delivery's `X-QF-Signature` (HMAC-SHA256 over `"{X-QF-Timestamp}.{body}"`), enforces a timestamp tolerance for replay protection, de-dupes on `X-QF-Event-ID`, and logs each event as JSON. Optional `--forward <url>` re-posts verified events downstream, and `--pull` fetches the received document + attachments. Binds to localhost (expose publicly via ngrok) and installs as a Windows service / systemd unit via `qfc service install`. The companion `qf-scsn-webhook` skill documents the end-to-end setup (run → ngrok → register → verify/replay).
- **MCP exposure of the SCSN Document Exchange API.** `qfc mcp` now also loads the docsexchanger spec and merges it with the backend spec, so its broker and webhook endpoints are discoverable and callable over MCP (`call_api` routes `/docsexchanger/…` paths to the host authority). Disable with `--no-docsexchanger`; the load is best-effort and falls back to the backend spec if unavailable.

### Changed
- **MCP surface map covers the SCSN tags.** `ScsnDocuments` is scoped to the Order (contributor) surface; `ScsnBrokerAgentManagement` and `SCSNManagement` to System (super-admin); and the docsexchanger `ScsnBroker` / `ScsnBrokerSandbox` / `ScsnBrokerWebhooks` tags to Order (contributor) — so these endpoints are scoped correctly instead of defaulting to the shared base surface. The backend continues to enforce the real per-endpoint authorization.

### Fixed
- **Removed a stale checked-in `swagger.json`.** A tracked copy at the repo root was picked up by the spec loader whenever the CLI ran from the repo root, shadowing the live/cached backend spec (so `api discover`/`describe` could miss newer endpoints). The CLI auto-fetches and caches the spec, so the checked-in copy is gone.
